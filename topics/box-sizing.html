Box Sizing: content-box vs border-box

By default, browsers use content-box sizing: the width you set applies only to the content area. Padding and border are added on top, making the element bigger than you might expect.

With border-box, the width you set includes the content, padding, and border. This usually makes layout math simpler and more intuitive, so many designers set border-box as the global default.

Visual Comparison

Both boxes below have the same declared CSS:

width: 200px;
padding: 16px;
border: 8px solid;

Only box-sizing is different.

Common Global Pattern

A simple, modern pattern for most projects is to set border-box for everything: 

/* Most common modern reset */
*, *::before, *::after {
  box-sizing: border-box;
}

This is easy to understand and matches what many tutorials, frameworks, and CodePen examples use.

Alternative “inherit” pattern (more advanced)

Some developers prefer to set box-sizing on html and then inherit it everywhere. This makes it easier to change box sizing for components if needed: 

html {
  box-sizing: border-box;
}

*, *::before, *::after {
  box-sizing: inherit;
}

For most beginners, the simple version is enough. The “inherit” version is useful if you ever need a specific component to behave differently.

Rule of thumb for this course:
Use border-box as your default. It makes widths more predictable, especially when you start adding padding and borders around cards, buttons, and layout columns.
