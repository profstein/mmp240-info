Cards

Intro

Cards are a very common UI component that allow you to list structured information in a scanable way. You use this when you have a number of items of the same type that both have a few pieces of structured info and need to be shown in a group.

Overview

Cards are one of the most common patterns in web design. You see them everywhere:

  • Product listings on shopping sites
  • Social media posts
  • News articles
  • Video lists on streaming platforms

A card groups together content and actions in a way that is both easy to see and use. Good card structure makes it easier to:

  • Style with CSS (Grid and Flexbox)
  • Reuse the structure in multiple scenarios
  • Extend with more features and functionality later

Structure

When making the structure for your card, each part of it should be organized into a container based on the type of content and how you are grouping the content in the card. This gives you something to style and makes layout easier.

These are some of the types of containers and content you typically see:

  • an image container that might also include category, icon if favorited etc.
  • a content container that is the main text content for the card (title, description)
  • an actions or meta container that can hold buttons, interactive ratings, or meta information like when it was posted or number of comments.

As cards get more complex (such as those that flip over to reveal details, or include share icons and ratings) they still follow the same principle — each type of content belongs in its own container.

Articles and Headings

If the card content includes a title and description and leads to a page or more information, it's common to make the card an article element. It's OK to make the title an h1 element in this article because it's kind of like a mini-page. However, you may find some html linters and people who say there should only be 1 h1 per page. You can also make the card title an h2 or other heading in the current document heirarchy. 

Cards that don't have this level of information can use divs to contain them.

Typical structure

Here is a typical structure for a card (in outline form)

  • article with card class
    • div with image class
    • div with content class
    • div with actions or meta class

Here is a more complete HTML. Adding classes to all of the containers is important for styling later. 

<article class="card">
  <div class="card-image">
    <img src="https://picsum.photos/id/1015/600/400" alt="Random placeholder image from Picsum" loading="lazy">
    <p class="category">Street</p>
  </div>
  <div class="card-content">
    <h2 class="card-title">Hip-Hop</h2>
    <p class="card-desc">
      Hip-Hop emphasizes rhythm and improvisation, blending street styles like breakdancing and freestyle with choreography in both solo and group performances.
    </p>
  </div>
  <div class="card-actions">
    <a class="card-button" href="#" aria-label="View Hip-Hop details">View</a>
  </div>
</article>

Breaking it down

  • <article class="card"> → wraps the entire card. Using <article> makes sense because each card can stand on its own as a piece of content.

  • <div class="card-image"> → groups the card’s main visual. This allows overlays like the category label to sit on top of the image.

  • <div class="card-content"> → groups the title and description. By keeping these together, we can easily align text and control spacing.

  • <div class="card-actions"> → groups the card’s interactive elements. Even if there’s only one button now, later we might add “Save,” “Share,” or “Favorite.”
